# NightMarket — Spring Boot + MongoDB Full-Stack MVP

NightMarket is a native Android campus marketplace backed by a Java 17 / Spring Boot REST API and MongoDB (supporting MongoDB Community Server locally and MongoDB Atlas in the cloud). It demonstrates core Java Object-Oriented Programming (OOP) principles while delivering a complete, demonstrable student-to-student marketplace experience styled after modern Figma designs.

## 2. API Endpoints

All endpoints are hosted under `/api/listings` and `/api/health`:

| HTTP Method | Endpoint | Request Body / Query | Description |
|---|---|---|---|
| `GET` | `/api/health` | None | Returns backend status and `"database": "CONNECTED"` |
| `GET` | `/api/listings/feed` | None | Retrieves all ACTIVE listing summaries for the marketplace feed |
| `GET` | `/api/listings/search` | `?q=<keyword>` | Full-text search across title, description, category, and author/brand |
| `GET` | `/api/listings/{id}` | Path variable `id` | Retrieves full listing detail including contact info, category summary, and safety checklist |
| `GET` | `/api/listings/mine` | None | Retrieves all listings created by the demo user (both Active and Sold) |
| `POST` | `/api/listings/add` | `CreateListingRequest` JSON | Creates and persists a category-specific `Product` subclass in MongoDB |
| `POST` | `/api/listings/{id}/mark-sold` | Path variable `id` | Transitions product status to `SOLD` and persists to database |

### Example Create Listing Request
```json
{
  "title": "Sony WH-CH720N",
  "description": "Noise cancelling headphones in excellent condition. Includes original case and cable. Used gently for one semester.",
  "price": 4200,
  "category": "ELECTRONICS",

  "sellerName": "Aarav Sharma",

  "sellerEmail": "aarav.sharma@campus.edu",
  "meetupArea": "Manipal University Jaipur · On campus",
  "negotiable": true
}
```

## 3. MongoDB Configuration

The application reads configuration through standard environment variables:

| Variable | Default Value | Description |
|---|---|---|
| `MONGODB_URI` | `mongodb://localhost:27017/nightmarket` | MongoDB connection string (Local or MongoDB Atlas) |
| `PORT` | `8080` | Port on which the Spring Boot application listens |
| `SEED_DATA_ENABLED` | `true` | When `true`, automatically inserts 5 seed campus items if collection is empty |
| `UPLOAD_DIR` | `./uploads` | Local upload directory path |

### Option A — Local MongoDB Community Server
Start the local MongoDB service on Windows. By default, Spring Boot will connect to `mongodb://localhost:27017/nightmarket`.

### Option B — MongoDB Atlas Cluster
1. Create a free M0 cluster on [MongoDB Atlas](https://www.mongodb.com/atlas).
2. Create a Database User with read/write access.
3. In **Network Access**, add `0.0.0.0/0` (for cloud deployment) or your current IP.
4. Copy the SRV connection string:
   ```properties
   MONGODB_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/nightmarket?retryWrites=true&w=majority
   ```
5. Place this variable in `.env` or set it in your system/Render environment variables. Never commit secret passwords to Git.

## 5. How to Run the Android App

1. Ensure the Spring Boot backend is running on `http://localhost:8080`.
2. Open the `android/` directory in **Android Studio**.
3. Allow Gradle to synchronize dependencies.
4. Start an Android Virtual Device (Emulator) running API 24 or higher.
5. Click **Run 'app'** (`Shift + F10`).

### Emulator vs Physical Device Networking
* **Android Emulator:** Uses `http://10.0.2.2:8080` to reach `localhost:8080` on the host machine. This is configured by default in `android/app/build.gradle`.
* **Physical Device:** Ensure the phone and computer are on the same Wi-Fi. In `android/gradle.properties`, set:
  ```properties
  nightmarketApiBaseUrl=http://<YOUR_COMPUTER_LAN_IP>:8080
  ```
* **Render Deployed Cloud Backend:**
  Set in `android/gradle.properties`:
  ```properties
  nightmarketApiBaseUrl=https://your-app-name.onrender.com
  ```
* **Dynamic In-App Switcher:**
  Tap the top-right options icon (`...`) on the Android Home screen to inspect or switch the backend URL live at runtime without recompiling!

## 7. Java OOP Architecture & College Viva Guide

This codebase was intentionally designed to showcase core Object-Oriented Programming (OOP) concepts in an explainable, practical manner suitable for university viva and academic evaluations.

### 1. Abstraction
* **Class:** [`com.nightmarket.domain.product.Product`](backend/src/main/java/com/nightmarket/domain/product/Product.java)
* **Explanation:** `Product` is declared `abstract`. It cannot be instantiated directly because an abstract generic "product" does not exist in isolation. It declares abstract methods that define a contract for subclasses:
  * `public abstract String getCategorySpecificSummary();`
  * `public abstract List<String> getSafetyChecklist();`
  * `public abstract void validateCategoryDetails() throws DomainValidationException;`

### 2. Inheritance
* **Hierarchy:**
  * `Product` (Abstract Base)
    * `Textbook extends Product` (Adds `isbn`, `courseCode`, `author`, `edition`, `hasMarkings`)
    * `Electronics extends Product` (Adds `brand`, `model`, `warrantyMonths`, `includesAccessories`, `workingBattery`)
    * `HostelEssential extends Product` (Adds `itemSubtype`, `durationUsedMonths`, `bulky`)
    * `Clothing extends Product` (Adds `size`, `genderFit`, `brand`, `material`)
    * `SportsFitness extends Product` (Adds `sportType`, `equipmentWeightKg`)
    * `GeneralProduct extends Product` (Fallback concrete implementation)
* **Explanation:** Subclasses inherit common attributes (`title`, `price`, `sellerId`, `status`, `createdAt`, `imageUrls`) and methods while specializing behavior and data fields unique to their domain.

### 3. Polymorphism
* **Demonstration:**
  In [`SimpleListingService.java`](backend/src/main/java/com/nightmarket/service/SimpleListingService.java):
  * When converting any `Product` to a `ListingDetailResponse`:
    ```java
    r.setCategorySummary(p.getCategorySpecificSummary()); // Dynamic dispatch
    r.setSafetyChecklist(p.getSafetyChecklist());         // Subclass-specific list
    ```
  * Calling `p.getCategorySpecificSummary()` on a `Textbook` outputs course and edition information, whereas calling it on an `Electronics` object outputs brand, model, battery status, and warranty.
  * During creation, `product.validate()` invokes `validateCategoryDetails()`, running polymorphic category validation rules at runtime without `instanceof` checks.

### 4. Encapsulation
* **Demonstration:**
  * All domain fields in `Product.java` are private.
  * Direct state modification is guarded. For example, status cannot be randomly set from outside; it must transition through explicit business methods:
    ```java
    public void markSold() {
        if (this.status == ListingStatus.SOLD) {
            throw new ProductAlreadySoldException(this.id);
        }
        this.status = ListingStatus.SOLD;
        this.updatedAt = LocalDateTime.now();
    }
    ```
  * View counts and favorite counts are encapsulated (`incrementViewCount()`, `decrementFavoriteCount()`) preventing arbitrary external overwrites.

### 5. Interfaces & Contract-Driven Design
* **Package:** `com.nightmarket.domain.interfaces`
* **Interfaces Implemented by `Product`:**
  * `Validatable`: Enforces validation contract (`validate()`).
  * `Searchable`: Defines search filtering contract (`matchesSearchCriteria(String query)`).
  * `Offerable`: Enforces minimum offer threshold validation (`canAcceptOffer(BigDecimal amount)`).
  * `Negotiable`: Enforces pricing negotiation status (`isNegotiable()`).
* **Repository Interface:** `ProductRepository extends MongoRepository<Product, String>` cleanly decouples data access logic from business logic.

### 6. Factory Method Pattern
* **Location:** [`SimpleListingService.createProduct(CreateListingRequest req)`](backend/src/main/java/com/nightmarket/service/SimpleListingService.java)
* **Explanation:** Encapsulates the instantiation of category-specific subclasses. Based on `req.getCategory()`, the factory constructs and populates the appropriate subtype (`Textbook`, `Electronics`, `Clothing`, etc.) without exposing object creation logic to the REST controller.

### 7. Exception Handling
* **Location:** [`com.nightmarket.exception.GlobalExceptionHandler`](backend/src/main/java/com/nightmarket/exception/GlobalExceptionHandler.java)
* **Custom Domain Exceptions:**
  * `ListingNotFoundException`: Returns HTTP 404 with structured error response.
  * `DomainValidationException`: Returns HTTP 400 for invariant violations.
  * `ProductAlreadySoldException`: Returns HTTP 409 for duplicate state transitions.
  * `MethodArgumentNotValidException`: Centralized Bean Validation errors.

### 8. Collections & Generics
* **Demonstration:**
  * Strongly typed collections: `List<Product>`, `List<ListingSummaryResponse>`, `Set<String>`.
  * Generics in Spring Data: `MongoRepository<Product, String>`.
  * Generics in Retrofit: `Call<List<Listing>>`, `Call<Listing>`, `Call<Void>`.
  * Java Streams API for sorting, filtering, and mapping in `SimpleListingService.java`.
